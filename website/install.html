IF MACOS BLOCKS THE FIRST LAUNCH

“Apple could not verify OverAI.”

The preview is ad-hoc signed and has not been notarized by Apple. macOS cannot verify it as an identified-developer release. Only approve it if you trust the official download and have checked its published checksum.

  1. Try opening OverAI from Applications once. Dismiss the warning with Done or OK.
  2. Open Apple menu → System Settings → Privacy & Security.
  3. Scroll to Security and find the message that OverAI was blocked. Click Open Anyway.
  4. Authenticate if asked, then click Open in the confirmation.

macOS saves the exception for future launches. If the button is missing, try opening the app again and return to Privacy & Security. A managed Mac may prohibit exceptions; ask its administrator.

A different warning?

If macOS reports malware, says the app will damage your computer, or reports a damaged/modified app, stop. Redownload from the official release, verify the checksum, and contact support. Do not use a Terminal bypass to dismiss those warnings.

Terminal fallback · the xattr method

For advanced users only. Prefer Open Anyway above. Use this only for a trusted, checksum-verified official preview already installed in /Applications.

First check that the bundled signature is intact:

codesign --verify --deep --strict --verbose=2 "/Applications/OverAI.app"

If verification fails, stop and download a fresh copy. An ad-hoc signature check confirms consistency, not the developer’s identity or absence of malware.

Then remove only OverAI’s quarantine attribute and open the app:

xattr -dr com.apple.quarantine "/Applications/OverAI.app"
open "/Applications/OverAI.app"

This bypasses the quarantine-based first-launch check for this app. It does not notarize, scan, or repair it. Do not run the command on a whole folder or disk, disable Gatekeeper, or use xattr -cr to clear every attribute. No sudo is included; if permission is denied, use the macOS approval flow or contact support.

Use your app’s exact path if you installed it elsewhere. “No such xattr” means the attribute is already absent; it does not prove that the app is safe.

Verify your download’s SHA-256 checksum

Download SHA256SUMS.txt from the same release. Run this in Terminal: 

cd ~/Downloads
shasum -a 256 OverAI-3.0.1-3005-preview-arm64.dmg

The full 64-character result must match the DMG line in SHA256SUMS.txt. A checksum detects changed content; it does not replace trust in the source.
